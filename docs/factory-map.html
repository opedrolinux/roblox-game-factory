The factory,
as it stands

Three layers, one assembly line, and a ladder of gates that each have to go green before the next is allowed to run. The last rung is you. Everything below it exists so that by the time a game reaches you, the only question left is whether it’s fun.

I

What it’s made of

The factory copies rather than shares. Every game is a full fork of the engine, so one game can never break another — and a fix in one has to be deliberately carried back.

Layer 1 — the machinery
.claude/

The robots and the safety rails. This is the part that builds games.

  • skills/ — new-game, build-features, build-game
  • skills/lib/ — gauntlet, gate-require, tier-status
  • workflows/ — 8 lanes: decompose, contract-pass, fan-out, integration-gate, adversarial-review, grade…
  • hooks/ — the fence, plus auto-format
Layer 2 — the engine
core/

The parts every game starts from: networking, saving, session locking, the service framework.

  • 26 source files
  • 105 / 105 tests green
  • forked into each game, never linked
Layer 3 — the products
games/

The actual games. One real one so far, carried all the way to a human playtest.

  • collect-sim — 46 source, 32 test files
  • 422 / 422 tests green
  • verified in a live Studio session
II

The line

A one-page spec goes in the left, a built and gated game comes out the right. It pauses for a human exactly twice — once to approve the plan before any real code is written, and once at the end to play it and land it.

III

The ladder

Each rung only runs if the one below it is green, and a game’s honest status is the highest rung it has actually reached — never a bare “ready.” The right-hand column is the useful one: what that rung physically cannot see. Every rung exists because something expensive got past the rung below it.

IV

The fence, and where things stand

The factory runs for hours unattended, which only works because there is a hard list of things it may never do on its own. Those get queued for you instead of done.

Never, without you
  • git pushLanding code is yours. It can commit locally; it cannot publish.
  • network callsNo uploading, no fetching, nothing outside the repo.
  • real moneyNo purchases, no publishing to Roblox, no account actions.
  • edit its own fenceThe guard protects its own config, so it can’t widen its permissions.
  • destructive gitRecovery is forward-only — revert, never reset or force.
